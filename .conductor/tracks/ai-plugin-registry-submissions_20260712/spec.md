# AI plugin and MCP registry submissions

## Overview

Prepare and submit the fyi-mcp server to every relevant AI plugin, MCP directory, and community catalog, while keeping live status evidence-backed.

## Scope

- OpenAI Codex plugin review/marketplace path.
- Anthropic Claude Connectors Directory submission path.
- Official MCP Registry, Glama, Smithery, GitHub curated MCP, PulseMCP, mcp.so, Docker MCP Catalog, OpenTools, and Awesome-MCP-Servers.
- Versioned manifests, screenshots/descriptions where required, security disclosures, privacy and write-action descriptions, and submission audit trail.

## Requirements

1. Every target has an owner, submission URL, prerequisites, package/version, and evidence state.
2. A target is marked live only after a public listing URL or authoritative API proof is recorded.
3. Codex and Anthropic submissions explicitly document server transport, authentication, exposed tools, write behavior, data handling, support contact, and rollback/version policy.
4. No external submission is silently retried, paid, or performed with a personal account without an auditable operator action.
5. Failed, rejected, or manual-curation targets remain visible as blocked-external with next review date.

## Acceptance criteria

- All relevant targets are classified as live, submitted, assets-ready, blocked-external, or not-applicable.
- Submission packets pass repository validation and contain no placeholder release hashes or URLs.
- Public evidence and response timestamps are recorded in the distribution matrix and follow-up runbook.
- Automated monitor checks only public state and never claims submission success without evidence.

## Out of scope

- Alaveteli server maintenance.
- Building new MCP functionality unrelated to submission requirements.
- Circumventing curation, authentication, payment, or anti-bot controls.
