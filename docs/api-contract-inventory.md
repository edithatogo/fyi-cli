## Pinned Alaveteli reference

The baseline is upstream commit [`3966415`](https://github.com/mysociety/alaveteli/commit/3966415f0b2a9f445fa3bb25c06eaeb75ded6609): [routes](https://github.com/mysociety/alaveteli/blob/3966415f0b2a9f445fa3bb25c06eaeb75ded6609/config/routes.rb), [API controller](https://github.com/mysociety/alaveteli/blob/3966415f0b2a9f445fa3bb25c06eaeb75ded6609/app/controllers/api_controller.rb), [API tests](https://github.com/mysociety/alaveteli/blob/3966415f0b2a9f445fa3bb25c06eaeb75ded6609/spec/controllers/api_controller_spec.rb), [signup tests](https://github.com/mysociety/alaveteli/blob/3966415f0b2a9f445fa3bb25c06eaeb75ded6609/spec/controllers/user_controller_spec.rb), [session tests](https://github.com/mysociety/alaveteli/blob/3966415f0b2a9f445fa3bb25c06eaeb75ded6609/spec/controllers/users/sessions_controller_spec.rb), and [confirmation tests](https://github.com/mysociety/alaveteli/blob/3966415f0b2a9f445fa3bb25c06eaeb75ded6609/spec/controllers/users/confirmations_controller_spec.rb).
The [official API prose](https://alaveteli.org/docs/developers/api/) describes `/api/v2/request` and `json` as a form field; the pinned route uses `/api/v2/request.json`, and its controller reads `request_json` or `correspondence_json` and a separate `state`. Resolve this discrepancy against the exact deployed version; do not assume either behavior on a fork.
The checked [paired fork revision](https://github.com/edithatogo/alaveteli/blob/58d2f13e089145307b0d1d5ca460d08cfb84384a/app/controllers/api_controller.rb) uses the same named parameters, but its deployed use has not been established.

The experimental authority API records external requests and correspondence. It does not establish an ordinary requester's signup, session or request-submission journey. The API controller uses the authority's `k` parameter; the fork-local bot header is a separate mechanism. User signup, confirmation, login and logout are web flows, not documented API operations.

## Contract Gaps And Residual Risk

- **high** `rust_sync_client`: The synthetic source profile differs from the pinned upstream controller on routes, authority authentication, parameters and response shapes; see the reference comparison below.
- **closed** `rust_sync_client`: HTTP 401/403/404/429/5xx responses are covered by mocked non-secret error contract tests.
- **closed** `rust_sync_client`: Malformed JSON, missing required fields, and unexpected optional fields are covered by regression tests.
- **medium** `rust_cli_sync_surface`: Push cannot yet produce an acquisition receipt. Local register-request does not submit or create a user account.
- **high** `rust_mcp_sync_surface`: Governed source writes are exercised against a synthetic profile, not proven against the pinned upstream controller or a deployed instance.
- **high** `legacy_python_api`: Python's mocked disclosure API requests follow the online prose's `json` field, not the pinned controller's named parameters; no live deployment is qualified.
- **closed** `legacy_python_api`: Authority `k` is redacted from the covered URL, structured metadata and legacy HTTP error paths; source compatibility and complete credential handling remain separate gaps.
- **medium** `archive_public_web`: Live public-web smoke remains opt-in to avoid network-dependent CI.
